# Scripts

## How to run

From the repository root (the directory containing `Run.py`), install the
Python dependencies listed at the end of this document, then run:

```bash
python Run.py
```

`Run.py` checks for locally available 2018 AOP reflectance and canopy height
model (CHM) tile pairs before asking for a site ID:

- **Matching pairs for one site:** automatically detects the NEON site ID,
  skips the AOP download script, and runs scripts 2 and 3 using the local imagery.
- **Matching pairs for multiple sites:** exits with an error. The pipeline
  processes one site at a time; move the other sites' imagery outside the
  searched directories before running again.
- **No matching pairs:** prompts for a NEON site ID (default: `ORNL`), then
  runs all three scripts in order, including the AOP download.

The site ID is validated against `NEON_terrestrial_site_IDs.txt` and passed to
the scripts through the `NEON_SITE` environment variable. Any script that fails
stops the pipeline.

After the site is determined, `Run.py` reuses the NEON API token saved in
`data/neon_token.txt` (gitignored), or prompts for a token and saves it there.
The token is passed to the scripts as `NEON_TOKEN`. **A token and internet
access are still required when using existing AOP tiles**, because the
vegetation structure wrangler downloads field survey data and queries the NEON
locations API. Get a token from your user account at neonscience.org.

Fixed parameters: AOP year **2018**, vegetation structure **RELEASE-2024**.
The pipeline does not automatically fall back to other years or releases.

Each script also runs standalone and falls back to `ORNL` if `NEON_SITE` is unset.
For standalone execution, set `NEON_SITE` and `NEON_TOKEN` as needed; run the
scripts in order, or skip script 1 if the necessary imagery is already present.
Script 3 requires the CSV generated by script 2.

### Using existing AOP imagery

Place the original NEON reflectance HDF5 and CHM GeoTIFF files in `data/refl/`
and `data/chm/`, respectively. Both file paths must include a directory named
`2018`. Preserve the original filenames. For example, to run the pipeline
using only the ORNL observation tower tile:

```text
data/
├── refl/
│   └── 2018/
│       └── NEON_D07_ORNL_DP3_744000_3983000_reflectance.h5
└── chm/
    └── 2018/
        └── NEON_D07_ORNL_DP3_744000_3983000_CHM.tif
```

NEON's original nested download directories also work. A matching pair must
have the same site ID, tile easting and tile northing, and both paths must
contain `2018`. The year is identified from the directory, not the filename.
The check uses filenames and paths, not the contents or georeferencing of the files.

One matching pair is enough to skip the AOP download, but successful
classification requires sufficient trees within the available imagery. When
using local imagery, the pipeline does not download missing tiles to expand
coverage. Trees outside the available reflectance tiles are not extracted.

For consistent canopy filtering, keep only matched 2018 reflectance and CHM
files for the selected site, with one copy of each tile. The classification
script searches local reflectance and CHM files independently: extra unmatched
reflectance tiles can still be processed, and additional CHM files from other
years may interfere with CHM matching.

To download the complete set of plot-containing tiles or switch sites, move
existing matching imagery outside the searched folders before running `Run.py`,
or run the download script directly with the desired site and token.

Downloaded AOP imagery and the saved API token are excluded from Git by
`.gitignore`. Generated classification CSVs, vegetation CSVs and maps are not.

## 1. `download_neon_reflectance_data_and_chm_tiles.py`

Works out which 1 km AOP tiles the site's field plots fall in, then downloads them.

- Reads `data/All_NEON_TOS_Plot_Centroids_V11.shp` and keeps rows where
  `siteID` matches the site.
- Floors each plot's easting/northing to a 1000 m grid to get tile origins,
  then drops duplicates. Errors if the site has no plots.
- Loops the tile list twice, calling `neonutilities.by_tile_aop` once per tile so
  only one tile is in memory at a time:
  - `DP3.30006.001` hyperspectral reflectance → `data/refl/`
  - `DP3.30015.001` canopy height model → `data/chm/`
- Both loops use `skip_if_exists=True`, so re-running resumes instead of
  re-downloading.

**Output:** NEON's nested directory tree under `data/refl/` and `data/chm/`,
containing `*_reflectance.h5` and `*_CHM.tif` tiles.

**Required input:** keep all components of `All_NEON_TOS_Plot_Centroids_V11`
(`.shp`, `.shx`, `.dbf`, `.prj`, `.cpg`) together in `data/`. The download
script is not needed when `Run.py` detects matching local AOP imagery.

## 2. `NEON_TOS_Vegetation_Structure_data_wrangler.py`

Turns the TOS field survey into per-tree points with a genus label.

Part 1 — coordinates:
- Loads `DP1.10098.001` (vegetation structure), RELEASE-2024.
- Takes `vst_mappingandtagging` and drops rows with a blank `pointID`.
- For each unique `namedLocation.pointID`, hits the NEON locations API
  (1 s sleep per call to stay under the rate limit) for the reference point's
  UTM easting/northing and uncertainties. Points missing from the location
  database are dropped.
- Converts each stem's `stemDistance` / `stemAzimuth` offset from its reference
  point into `adjEasting` / `adjNorthing`.

Part 2 — stem heights:
- Loads `vst_apparentindividual`, keeps the most recent survey event per
  individual, keeps only `plantStatus == "Live"` with a positive height, and
  keeps the tallest stem per `individualID`.
- Inner-joins that onto the mapped coordinates.
- Derives `genus` as the first word of `scientificName` and keeps the 15 most
  abundant genera (`top_amount`).

**Output:**
- `data/veg_structure_data_by_genus_<SITE>.csv`
- `data/tree_genus_map_<SITE>.png` — map-view scatter coloured by genus

## 3. `tree_genus_classification.py`

Extracts a spectrum per tree and compares three classifiers.

- Reads the site CRS off the first CHM GeoTIFF with `rasterio` rather than
  hard coding an EPSG. This assumes the field UTM coordinates use the same
  CRS as the imagery.
- Loads the stage 2 CSV into a GeoDataFrame in that CRS and assigns each tree to
  its 1 km tile, then matches tiles to locally available 2018 HDF5 files.
  A single tile or multiple tiles can be used.
- **CHM filter:** samples the CHM at each tree's location and drops stems more
  than `height_tolerance` (5 m) below canopy height — i.e. understory stems whose
  crown is not what the sensor sees. Trees with no CHM coverage are kept.
- `aop_h5refl2xarray()` reads a reflectance HDF5 into an `xarray.Dataset`
  (copied from the NEON pyXarray tutorial). It also flags bad bands: the two
  water-absorption windows from the file metadata plus the last 10 bands.
- For each tree, takes the single nearest pixel's full spectrum via
  `np.argmin` on the x/y coordinate arrays.
- Exits with an error if no tree spectra are extracted.
- Drops bad bands and excludes genera with fewer than 3 extracted samples.
  Exits with an error if fewer than 3 genera remain.
- Performs a stratified 80/20 train/test split, `StandardScaler`, then
  `PCA(n_components=5)`.
- Fits Random Forest (200 trees), RBF SVM (C=10, gamma=0.1) and an MLP (32, 16),
  printing accuracy, macro OvO ROC AUC and a classification report for each.

**Output:** `data/NEON_<SITE>_Genus_Classification_Results.csv` — per-genus
precision/recall/F1/support plus pairwise OvO AUC, macro and weighted averages,
and an overall accuracy and macro OvO AUC row, for all three models.

**Small datasets:** three samples per genus is a minimum inclusion threshold,
not a guarantee that the stratified 80/20 split will succeed or that every genus
will be represented in both subsets. Multiclass ROC AUC requires all retained
genera to be represented in the test set. If a single tile provides insufficient
samples, add more matching tiles from the same site or use the full download
workflow. The five-component PCA also requires at least five training samples
and five retained bands.

### Known quirk inherited from the NEON tutorial

In `aop_h5refl2xarray`, this line:

```python
refl_arrayT = np.transpose(refl_array, (1, 0, 2))
refl_arrayT = refl_array[::-1, :, :]
```

The transpose is immediately discarded by the second assignment. This matches
the upstream tutorial and has been left as-is; the y coordinates are built
ascending to match the flipped array. Spatial orientation and pixel coordinate
alignment should be verified against georeferenced imagery before relying on
classification results at a new site.

## Dependencies

Install the required Python packages in your active environment:

```bash
python -m pip install numpy pandas geopandas rasterio h5py xarray scikit-learn neonutilities matplotlib seaborn requests
```

Use the same Python environment to run `Run.py`. Ensure the `data/` directory
exists before the first run so the API token and generated outputs can be saved.
